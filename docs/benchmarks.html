Two attributed remaining gaps:

  • **jsonparse 0.6× (10-27 third round: 8.0-8.5ms vs rust 4.5-4.8ms, post

materialization pooling)**: three-layer attribution (construction 12% / materialization the bulk) and fix chain — v1.11.4's pool was initially attached to the zero-call rawstr_char_at (its 0.8ms gain was noise, corrected); the real hot path was s[i]'s view→RAWSTR materialization (rawstr_new_copy: 2 mallocs + memcpy + SIMD code-point count, ~62ns/char). This round connected materialization to rawstr_char1 (one-byte code points serve from a 256-entry shared pool, cap=-1 immortal sentinel): scan probe 9.9→4.7ms, **at parity with the hand-written ord() idiom (62→~5ns/char), jsonparse 9.8→8.0-8.5ms. Inline strategy measured and rejected**: clang -O2 already inlines small runtime functions (verified in assembly); the remaining single char1 call with alwaysinline actually regressed 4.64→4.91ms (icache damage). **Remaining gap ≈ construction cost 1.9ms (pure-runtime 5.2 vs 3.5ms, gap 1.7ms)** — sum-types (RFC S1-S4) promoted from "secondary" to the closing critical path: post-materialization construction share rose from 12% to ~24%.

  • wordcount 0.6× (10-27 retest): v1.11.3's subscript type inference

eliminated w = vocab[i]'s pyobj boxing (.ll call sequence verified), but exposed a deeper layer: rawlist_str_get has copy semantics (slots own copies) — each read mallocs a new block + frees the old slot, two heap operations actually costlier than single boxing. A/B measured (old .ll 21.2ms vs new 24.3ms, 15-run min each). The fix = borrowed reads (immutable-element subscripts return borrowed pointers) or buffer reuse (rawstr_copy_into, Rust's clone_from approach) — the same immutable-value copy-semantics family as jsonparse's char access, treatable together.

4. Methodology Notes

  • Four planes, verify before timing: each program first confirms

interpreter/CPython/compiled-artifact/Rust-twin outputs are identical; otherwise the row is marked MISMATCH and excluded.

  • CPython plane goes through the pycompat shim (Silu classes use positional

constructors, differing from bare CPython semantics); Rust twins are hand-mirrored per program and output-compared.

  • Compile timing is median of 3; startup baseline separately deducted

(4.3ms silu / 2.3ms rust empty program).

  • Per-item attribution uses ablation + macOS sample profiling (example:

jsonparse's 70ms hot zone was sampled and pinned to parameter deep-copy; fixed to 8.3ms).
